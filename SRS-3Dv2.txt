1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) defines the functional, technical, and operational requirements for the 3D Interactive Real Estate Portal, a web-based platform that enables real estate developers to digitally showcase residential, commercial, and mixed-use projects through immersive 3D visualization, interactive maps, virtual tours, and comprehensive project management tools.
The portal will support multiple developers and multiple projects within a single platform while providing a seamless experience for local buyers, overseas investors, sales agents, and administrators.
The objective is to replace traditional brochures and static project websites with an interactive, data-driven property exploration platform capable of generating qualified leads, improving customer engagement, and increasing property sales.

1.2 Business Objectives
The portal aims to achieve the following business goals:
Primary Objectives
* Digitally showcase multiple real estate projects on a single platform. 
* Increase qualified lead generation. 
* Improve buyer engagement through immersive 3D experiences. 
* Enable overseas investors to evaluate projects remotely. 
* Reduce sales cycle through online virtual tours. 
* Provide centralized project and inventory management. 
* Support multilingual content and multiple currencies. 
* Integrate with CRM systems for automated lead management. 
* Reduce operational costs through self-hosted GIS and 3D technologies. 
Secondary Objectives
* Improve project discoverability. 
* Provide accurate property information. 
* Automate booking workflows. 
* Increase transparency of inventory availability. 
* Provide actionable analytics for developers. 

1.3 Project Vision
The platform will become a centralized digital marketplace where real estate developers can publish projects with interactive 3D visualization, allowing buyers to explore projects almost as if they were physically present.
Unlike conventional property portals, the system will combine:
* GIS Mapping 
* 3D Models 
* Virtual Tours 
* Unit Availability 
* Interactive Floor Plans 
* ROI Calculators 
* Distance Analysis 
* Lead Management 
* Booking System 
into one integrated platform.

1.4 Reference Website Review
The following reference sites were reviewed to align the portal with current real estate marketing expectations.
* suncitymonarch.com 
  - Strong project landing page with clear configuration, pricing and RERA details. 
  - Prominent WhatsApp, phone call, and appointment booking CTAs. 
  - Dedicated navigation for Gallery, Location Map, 360° View, and Walkthrough. 
  - Mobile-first enquiry flow and strong visual storytelling.

Key takeaways:
* Project pages should promote direct lead capture through WhatsApp, phone, email, and appointment booking.
* Public pages should include location, gallery, walkthrough/360 view, project features, and regulatory information.
* Buyer journeys should support quick inquiry, guided booking, and instant contact actions from all project views.

4. Assumptions
The following assumptions apply.
1. Developers will provide complete project information. 
2. Developers will provide accurate unit inventory. 
3. Every project will have accurate GPS coordinates. 
4. 3D models will be prepared externally. 
5. Internet connectivity is available. 
6. Users will access the system using modern browsers. 
7. Developers are responsible for updating inventory. 
8. Currency exchange rates are available through external APIs. 
9. CRM APIs remain available. 
10. WhatsApp Business API credentials are provided by the client. 

5. Constraints
The solution must operate under the following constraints.
Technical
* Linux VPS hosting (Hostinger) 
* PostgreSQL database 
* Docker deployment 
* Open-source GIS technologies where possible 
* Minimal dependency on paid APIs 

Business
* Arabic and English only (Phase 1) 
* Self-hosted 3D assets 
* Support local and overseas investors 
* Cloud migration optional 

Operational
* Role-based approvals 
* Data backups 
* Audit logs 
* GDPR-compliant data handling (where applicable) 
* Country-specific privacy compliance if operating in multiple jurisdictions 

6. Success Criteria
The project shall be considered successful when:
* Multiple developers can independently manage projects. 
* Buyers can browse and search projects smoothly. 
* Interactive 3D visualization loads successfully. 
* Unit availability is displayed accurately. 
* Lead information is synchronized with CRM. 
* Site visits can be scheduled online. 
* Reservation workflow functions correctly. 
* Portal supports Arabic and English. 
* Mobile responsiveness is fully supported. 
* Performance targets are achieved. 

7. Out of Scope (Phase 1)
The following features are intentionally excluded from the first release.
* Online property purchase 
* Payment gateway integration 
* Blockchain ownership verification 
* Mortgage approval workflow 
* AI property valuation 
* VR headset support 
* Native Android application 
* Native iOS application 
* Property rental management 
* Smart home integration 
* Augmented Reality visualization

Section 4 � Interactive 3D Visualization, GIS Mapping & Property Discovery

27. Interactive 3D Visualization Module
Module ID: FR-400
27.1 Description
The Interactive 3D Visualization Module provides an immersive environment that allows users to explore projects, buildings, amenities, and units in a geographically accurate 3D environment. The platform shall integrate GIS data with custom 3D models to provide a realistic and engaging property exploration experience.
The system shall support streaming optimized 3D models to desktop and mobile browsers while maintaining acceptable performance.

27.2 Functional Requirements
FR-401 3D Map Viewer
The system shall provide an interactive 3D map viewer capable of:
* Displaying projects on a geospatial map 
* Rendering custom 3D building models 
* Supporting smooth navigation 
* Zooming 
* Panning 
* Rotation 
* Tilt 
* Full-screen mode 
The viewer shall support mouse, keyboard, and touch interactions.

FR-402 Supported Map Layers
The platform shall support configurable base map providers, allowing the portal owner to choose one or more sources.
Examples include:
* OpenStreetMap 
* MapLibre-compatible vector tiles 
* Cesium World Terrain 
* Self-hosted map tiles 
* Commercial providers (optional) 
The selected map provider should be configurable without requiring application code changes.

FR-403 Project Rendering
Each project shall be displayed using:
* Geographic coordinates 
* Project boundary (polygon) 
* Building footprints 
* Custom 3D models 
* Project labels 
* Project status indicators 

FR-404 Building Rendering
Each building shall support:
* Accurate geographic positioning 
* Individual selection 
* Highlight on hover 
* Building information popup 
* Visibility toggling 
* Floor selection 

FR-405 Building Information
When a building is selected, the system shall display:
* Building Name 
* Building Type 
* Number of Floors 
* Available Units 
* Construction Status 
* Estimated Completion 
* Building Images 
* Quick Actions 

28. 3D Model Management

The platform shall support optimized web formats such as:

* Compress textures

Data Model Recommendations
To make the solution robust and scalable, I recommend the following design principles:
* Use UUIDs as primary keys instead of auto-increment integers. This simplifies data synchronization and distributed systems. 
* Use soft deletes (DeletedAt) for transactional data such as Projects, Units, Leads, and Bookings to preserve history and support recovery. 
* Store dynamic or structured attributes (e.g., camera positions, multilingual content, configuration) in JSONB where appropriate, while keeping core searchable fields normalized. 
* Track creation and modification metadata (CreatedAt, UpdatedAt, CreatedBy, UpdatedBy) on all major entities. 
* Use lookup/reference tables for configurable values (statuses, categories, currencies, languages) instead of hard-coded enums if administrators need to manage them.
